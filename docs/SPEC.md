# 留学カウンセリングAIチャットボット — Claude Code 実装プロンプト

> **使い方**: このファイルの内容をそのまま Claude Code に渡すか、リポジトリ直下に `PROMPT.md` として置き、「PROMPT.md の仕様に従って実装して」と指示してください。技術スタックは「前提」であり、変更したい箇所があれば Claude Code に伝えれば置き換わります。

---

## 0. ゴールと背景

留学を検討している日本語ユーザー向けの、AIカウンセリング・チャットボットを実装する。単なるFAQボットではなく、**カウンセラーのように対話しながら、ユーザーの目的・潜在ニーズを引き出し、構造化されたカルテを自動生成する**ことが目的。

このボットは以下を段階的に扱う（詳細は §3）：

1. 目的の整理・壁打ち（本当に留学すべきか、なぜ今なのか、を一緒に見つめ直す）
2. 条件のヒアリング（予算・期間・語学レベル等）
3. エリア（国・都市）の方向性の提案
4. （将来）語学学校・留学エージェントの提案

**重要な設計思想**: このボットは中立的であること。「行かない」という結論も一緒に検討できる立場を取る。押し売りをしない。これがこのサービスの信頼の核になる。

**将来**: このウィジェットを留学エージェントや語学学校のHPに script タグ1行で埋め込めるようにする（§6）。そのため最初から埋め込み前提の構成で作る。

## 1. スコープ

### MVP（今回実装する）
- 会話型のカウンセリングUI（テキストチャット、ストリーミング応答）
- §5 のシステムプロンプトに基づく段階的カウンセリング
- 対話の進行に合わせて**カルテ（構造化JSON, §4）を裏で更新**
- 会話の区切りで、収集済みのカルテ要約をユーザーに提示し、確認してもらう
- HPに埋め込めるウィジェット形態（iframe + ローダースクリプト, §6）
- UIは日本語

### 非スコープ（将来。今回は作らない。ただし拡張しやすい設計にしておく）
- エリア／エージェント／学校DBとのマッチングエンジン
- 音声カウンセリング（Realtime API）
- 管理画面・CRM連携・カルテのエクスポート
- 予約自動化・学校/エージェントへの連絡自動化

上記の将来機能は、コード内に該当箇所のインターフェース（例: `matchOptions(karte)` のスタブ）だけ用意し、TODOコメントで拡張ポイントを明示すること。

## 2. 技術スタック（前提。変更可）

- **フレームワーク**: Next.js（App Router）+ TypeScript
- **スタイル**: Tailwind CSS
- **LLM**: Anthropic API（`@anthropic-ai/sdk`）。モデルは環境変数で切替可能にし、既定は最新の Claude を使用
- **応答**: サーバー側 API Route でストリーミング（SSE）。APIキーは絶対にクライアントに露出しない
- **状態管理**: MVPはフロントのReact state + サーバーのセッション単位メモリで可。永続化DBは将来（インターフェースだけ切っておく）
- **環境変数**: `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`（任意）

APIキーは `.env.local` から読み、`.env.example` を用意すること。

## 3. カウンセリング設計（対話フロー）

ボットは以下のステージを、会話の自然な流れの中で進める。**厳密なステートマシンで固定順序を強制するのではなく**、システムプロンプトでステージの意図を持たせ、ユーザーの反応に応じて柔軟に行き来する。ただし現在のステージを内部的に把握し、カルテに記録する。

1. **ラポール形成 / 来訪動機**: なぜ留学を考え始めたのかを、まず聞く。
2. **動機の深掘り・壁打ち（最重要）**: 「なぜ今なのか」「留学で何を得たいのか」「それは留学でしか得られないのか」を、決めつけずに質問で整理する。ここで“行かない”選択肢も否定しない。
3. **条件ヒアリング**: 目的・予算・期間・渡航時期・語学レベル・年齢・就労希望・環境の好み・進学意向・制約を、1つずつ自然に聞き出す。
4. **エリアの方向性提案**: 集めた条件から、国・都市の方向性を仮提案し、すり合わせる（確定ではなく対話）。
5. **（将来）学校・エージェント提案**: MVPでは「ここから先は担当者/次のステップでご案内します」と案内し、カルテ確認に進む。
6. **要約・カルテ確認**: 収集した内容を要約提示し、ユーザーに認識のズレがないか確認してもらう。

**対話ルール**（システムプロンプトに反映）:
- 一度に質問を詰め込まない（原則1ターン1問）
- 専門用語を避け、平易に
- 共感的だが簡潔
- 押し売り・誘導をしない。中立を保つ
- 学費・ビザ・為替など変動する情報は「一般的な傾向」として扱い、最新の正確な数値は要確認である旨を必要に応じて添える
- ユーザーのお金（学費等）は預からない前提で会話する

## 4. カルテ（構造化データ）スキーマ

対話の進行に合わせて、以下のJSONを段階的に埋めていく。未取得の項目は `null`。TypeScriptの型として定義すること。

```ts
type Karte = {
  // メタ
  sessionId: string;
  currentStage: "rapport" | "motivation" | "conditions" | "area" | "proposal" | "summary";
  updatedAt: string; // ISO

  // 動機・潜在ニーズ（②の中身。自由記述で厚く残す）
  triggerReason: string | null;   // なぜ留学を考え始めたか
  whyNow: string | null;          // なぜ今なのか
  desiredOutcome: string | null;  // 何を得たいか
  latentNeeds: string | null;     // 対話から読み取れた本当の動機
  readinessNote: string | null;   // 本当に行くべきか、の整理メモ

  // 条件
  purpose: ("language" | "university_prep" | "career" | "working_holiday" | "experience" | "migration")[] | null;
  budgetTotalJPY: number | null;
  budgetMonthlyJPY: number | null;
  durationWeeks: number | null;
  departureTiming: string | null; // 例 "2026年秋"
  languageLevel: string | null;   // 例 "TOEIC 600 / 日常会話は不安"
  age: number | null;
  wantsToWork: boolean | null;
  environmentPrefs: string | null; // 都会/自然, 多国籍/日本人少なめ, 気候, 治安 等
  wantsPathway: boolean | null;    // 進学（大学・専門）意向
  constraints: string | null;      // ビザ/仕事/家族 等

  // 提案（MVPでは方向性メモまで）
  suggestedAreas: string | null;

  // 次アクション
  decisionStatus: "exploring" | "leaning_yes" | "leaning_no" | "decided_yes" | "decided_no" | null;
};
```

**カルテ更新の実装方針**（推奨）: 会話を汚さないため、カルテ更新は Anthropic API の **tool use** で行う。`update_karte` というツールを定義し、モデルがユーザー発話から抽出できた項目だけを部分更新（差分マージ）する。ツール呼び出しはユーザーには見せず、テキスト応答だけをストリーミング表示する。tool use が難しければ、応答とは別に軽量な抽出用の非ストリーミング呼び出しを1回挟む方式でもよい。

## 5. チャットボットのシステムプロンプト（実装に埋め込む本体）

以下を、カウンセリング担当LLMの system プロンプトとして実装に埋め込む（定数として切り出し、後から編集しやすくする）。日本語のまま使う。

```
あなたは「留学カウンセラーAI」です。留学を検討している日本語話者に、信頼できる中立的なカウンセラーとして寄り添います。

# あなたの役割
- ユーザーの目的や、本人もまだ言語化できていない潜在的な動機を、対話を通じて引き出し、一緒に整理する。
- 必要であれば「今は留学しない」という結論も一緒に検討する。留学を勧めることがゴールではない。ユーザーが自分の気持ちを整理し、納得して次の一歩を決められることがゴール。

# 対話の進め方（内部的な段階。順序は柔軟に）
1. まず、なぜ留学を考え始めたのかを聞く。
2. 「なぜ今なのか」「留学で何を得たいのか」「それは留学でしか得られないのか」を、決めつけずに質問で整理する（壁打ち）。
3. 目的・予算・期間・渡航時期・語学レベル・年齢・就労希望・環境の好み・進学意向・制約を、自然な流れで一つずつ聞く。
4. 集めた条件から、国・都市の方向性を仮に提案し、感触をすり合わせる。
5. 最後に、話した内容を要約して提示し、認識のズレがないか確認する。

# 話し方のルール
- 一度にたくさん質問しない。原則、1回の返答につき質問は1つ。
- 温かく共感的に。ただし冗長にならず簡潔に。
- 専門用語は避け、平易な言葉で話す。
- 押し売りや誘導をしない。中立を保つ。
- 学費・ビザ・為替など変わりやすい情報は「一般的な傾向」として話し、正確な最新情報は各機関での確認が必要だと必要に応じて添える。断定しすぎない。
- 学費などのお金をこのサービスで預かることはない、という前提で話す。
- ユーザーが不安や迷いを見せたら、まずその気持ちを受け止めてから進む。

# してはいけないこと
- 特定のエージェントや学校を、根拠なく強く勧めること。
- ユーザーの発言を無視して次の質問に進むこと。
- 事実でない具体的数値（学費・合格率など）を断定的に述べること。
```

**カルテ抽出用ツール定義**（tool use を使う場合）: `update_karte` を定義し、入力スキーマは §4 の `Karte` の各フィールド（すべて任意）。「今回の直近のやり取りから新たに判明した項目のみ」を渡すようモデルに指示する。

## 6. 埋め込み（ウィジェット）要件

将来、留学エージェントや語学学校のHPに簡単に設置できるようにする。以下を満たす構成にすること。

- チャットUIを、単独で成立する埋め込み用ページ（例: `/widget`）として用意する。
- ホストサイトには **script タグ1行**で設置できるローダー（例: `public/embed.js`）を用意し、右下に起動ボタン→クリックで `/widget` を iframe で開く、という一般的なチャットウィジェット挙動にする。
  ```html
  <script src="https://<your-domain>/embed.js" data-key="TENANT_KEY" async></script>
  ```
- `data-key` でテナント（設置元エージェント/学校）を識別できるようにし、将来テナントごとに文言や提案先を出し分けられるよう、値をウィジェットに引き渡してカルテの `sessionId` 周辺に保持する（マルチテナントの土台。MVPでは値を保持するだけでよい）。
- iframe と親ページ間は `postMessage` で最小限の通信（開閉、必要なら高さ調整）。
- CORS / `X-Frame-Options` / CSP を、外部ドメイン埋め込みが可能な設定にする（少なくとも開発時は緩めに、本番は許可ドメインを絞れるコメントを残す）。

## 8. 実装の進め方（この順で）

1. Next.js + TS + Tailwind の雛形を作り、`.env.example` を用意。
2. `/api/chat` で Anthropic のストリーミング応答を実装（まずカルテ抽出なしで、システムプロンプトだけで会話が成立することを確認）。
3. チャットUI（`/widget`）を実装。ストリーミング表示、送信中状態、エラー処理。
4. `update_karte` ツールを追加し、対話中にカルテが差分更新されることを確認。開発中はカルテを画面横（またはデバッグパネル）に表示できるようにする。
5. 会話の区切りでカルテ要約（`KarteSummary`）を出し、ユーザー確認を取るステップを追加。
6. `embed.js` と iframe 起動を実装し、別の簡易HTMLから設置テスト。
7. README にセットアップと埋め込み手順を記載。

各ステップ後に動く状態を保ち、こまめに動作確認できるようにすること。

## 9. 制約・注意

- **お金を預からない**: 学費等の決済・預かりは実装しない。会話上もその前提を守る（法規制上の理由）。将来の申込導線は「エージェント/学校側へ送客」を想定。
- **個人情報**: カウンセリングで機微な情報を扱う。MVPでも、収集項目の説明と、外部送信されるのはLLM推論のためである旨を明示する簡単な同意/注意書きをUIに置く。ログに個人情報を不用意に残さない。
- **中立性**: システムプロンプトの中立ルールを弱めないこと。将来マッチングや送客報酬を実装する際も、この方針を壊さない前提でインターフェースを設計する。
- **正確性**: ビザ・学費・入学要件などをボットが断定しない。変わりうる情報である旨を扱いに含める。
